Modular I/O Configuration

Pick the actual MaxxECU channel for each sensor. Changes automatically re-analyze the currently loaded log. AUTO only runs when no manual channel is selected.

Export saves your channel picks by name (not by position), so a friend with a different AIN/DIN layout can import it as a starting point and only needs to fix what doesn't auto-match. Config lives in this browser only — export it before switching devices.

Conversions: Fuel pressure = KPA → PSI. Oil pressure = BAR → PSI. MAP/boost = KPA → PSI (gauge, minus 14.7 psi sea-level baseline). Temperature = °C → °F. TPS/Ethanol = %. Battery = V. Speed = km/h → mph. Ignition timing/knock retard = degrees, unconverted.

What this is

PULLSHEET reads MaxxECU M-Tune log exports (.MaxxECU-Zip-log or .MaxxECU-Log) entirely in your browser — nothing is uploaded anywhere, ever. Drop a log to get a health check, a zoomable trace of every channel, WOT pull breakdowns, and a copyable report you can hand to a tuner. Plain CSV exports from other standalone ECUs work too, since channel detection matches on plain header text as well as MaxxECU's own convention — Holley EFI's datalog viewer has a CSV export button for exactly this (Holley's native .dl/.dlz files are a different binary format and can't be dropped in directly). Auto-detect won't be perfect on a non-MaxxECU log, so check the I/O Config tab and fix anything it missed by hand.

Getting the most out of it

Drop a .MaxxECU-Zip-log rather than a plain .MaxxECU-Log when you can — the zip bundles your tune save file inside it, which this tool reads automatically to auto-map your fuel/oil/AC pressure sensors by the names you actually gave them in MaxxECU, pull your real rev limiter and warning thresholds, and catch sensor calibration mistakes before they show you a wrong number. If a channel doesn't auto-detect right, the I/O Config tab lets you point any sensor at any column in the log by hand — that choice is saved in this browser and can be exported/imported as a starting point for someone else's car.

Using this on your phone

This is a single HTML file, not an app — get it onto your phone however's easiest (AirDrop, Google Drive, iCloud, email it to yourself) and open it from your Files app or cloud storage app using "Open in browser" if that option shows up, or just tap it and pick your browser when prompted. Once it's open, use the browser's Share → Add to Home Screen option — it'll launch full-screen from an icon like a real app afterward, no browser address bar. Your config picks, saved drive history, and unit preferences all live in that browser only, so use the same browser/device each time if you want them to stick — export your I/O config from the Config tab first if you're switching phones or browsers.

Known limitations

The ZF8HP70 TCU's own "Drive Mode" channel isn't decoded to a name — MaxxECU doesn't store a text label for it the way it does for the engine tune-map selector, so it shows as a raw number. Health scoring only grades a channel when the numbers look physically plausible against that session's own sensor calibration — if they don't, the tool says so instead of guessing. This is built and tested against a MaxxECU + ZF8HP70 LS-swap setup specifically; other transmissions or ECUs will still get the universal channels (RPM, AFR, temps, fuel/oil pressure) but not the 8HP-specific extras.

Recent fixes

v1.7 — Three more. (1) Dyno curve overlay: 2+ pulls in the same log now get an extra chart overlaying every pull's power curve on one graph — actually see if a tune change made more power, instead of eyeballing separate charts. (2) Launch analysis: a new table breaking down the first couple seconds of each standing-start pull — launch RPM, launch boost, 60-ft time, and a heuristic flag for possible wheel or converter slip (RPM climbing hard before the car is actually rolling). (3) Nitrous safety: add a nitrous activation channel in Config I/O and the app now watches specifically for lean or knock events WHILE nitrous is active, using a much tighter threshold than normal (a lean nitrous hit is how pistons get holes in them) — shown as bright pink "NITROUS LEAN"/"NITROUS KNOCK" flags plus a dedicated Nitrous dashboard card (activation count, total active time, worst AFR seen).

v1.6 — Four more. (1) Power/torque curves: any pull with usable power data now gets an expandable RPM-based chart (like a real dyno sheet) instead of just one peak number — clearly labeled as MaxxECU's engine-side fuel-flow estimate, not a wheel-HP dyno reading. (2) Trend alerts: your log history now watches for slow-building problems — knock, coolant/trans temp, health score, or AFR drift worsening over several consecutive logs for the same vehicle — and flags them on the History tab before they're obvious. (3) Session card: one button now builds a single shareable image summarizing the WHOLE session (best pull, health, any PRs, issues flagged), not just one pull. (4) Dashboard cards are now toggleable — only RPM, boost, power, knock, and AFR show by default, with everything else (coolant, injector duty, gear range, etc.) a single tap away instead of an 18-card wall every time.

v1.5 — Three new features. (1) Flagged issues: every pull now gets auto-scanned for real knock events, lean spots vs. target AFR, boost spikes, and heat-soaked intake air — surfaced as a chip list under the WOT pulls table and as colored triangle markers right on the timeline chart, so problems jump out instead of hiding in the numbers. (2) Gear-by-gear breakdown: any pull that shifts through multiple gears (detected from the gear channel) gets an expandable table showing time, RPM in/out, speed, peak boost, and knock for each individual gear. (3) Personal records: 0-60, 1/8 mile, peak power, peak torque, and peak boost are now tracked per vehicle across your log history — beat a previous best and a "NEW PERSONAL RECORD" banner shows up right at the top of the results.

v1.4.2 — Updates now actually show up: previously, shipping a new version didn't refresh an already-open tab or installed app — the new code loaded in the background but nothing told the page to reload, so it kept running the old version until you happened to fully close and reopen it. Now the app reloads itself automatically the moment an update finishes installing. (If you're reading this changelog entry, it worked.)

v1.4.1 — Hardened the offline service worker: it used to cache the whole app shell as one all-or-nothing batch, so a single flaky request during an update (spotty signal at the exact moment a new version installs) could silently leave the cache empty and the old, working cache already deleted — causing "Chart is not defined"/"JSZip is not defined" errors. Now each file caches independently, one bad fetch doesn't take the rest down with it, and a previous working cache is kept if an update can't get anything new cached at all.

v1.4 — Peak power/torque now parsed straight from MaxxECU's own fuel-flow-calculated channels and shown on the dashboard, chart, and WOT pulls table (not a dyno figure, but real logged data). Each WOT pull can now generate a shareable square summary image (0-60, boost, knock, power) via a CARD button — built for texting/sharing, not just the full tuner report. History trend chart now has a Performance view (peak boost/knock/AFR delta across saved sessions) alongside the existing Reliability view.

v1.3 — Fixed knock retard auto-detect grabbing the wrong column on real MaxxECU exports (a "Retard reason" status code, not a degrees value — showed up as absurd numbers like 1024°). Now matches MaxxECU's actual "Knock correction" channel, and ignition timing auto-detect matches MaxxECU's actual "Ignition angle" channel too. Knock retard peaks are also computed correctly regardless of whether the log stores it as a negative delta or a positive magnitude.

v1.2 — Works fully offline after the first load (JSZip/Chart.js/ the zoom plugin are bundled locally now instead of loaded from a CDN, plus a service worker caches the app itself — useful with no signal at the track). Channel auto-detect now also recognizes plainer CSV header styles, so exports from other standalone ECUs (Holley EFI's CSV export, Haltech, AEM, Link) can be dropped in, not just MaxxECU's own convention. History entries can be tagged by vehicle and filtered, for anyone logging more than one car. Added iOS splash screens and a clearer error when a file picked from Files is an undownloaded iCloud placeholder.

v1.1 — MAP/boost, intake air temp, ignition timing and knock retard are now parsed and shown on the dashboard, chart, and report; WOT pulls table adds estimated 0-60/eighth-mile times (integrated from the logged speed trace, only shown for pulls that actually start near a stop), plus peak boost and knock per pull; new Compare tab for a side-by-side delta between two logs; Share button (native share sheet on iOS) and Print/Save PDF alongside Copy Report; file picker no longer restricts by extension, fixing it being unable to see MaxxECU log files on iOS.

v1.0 — WOT/AFR stats now exclude neutral throttle blips from driving pulls; automatic calibration-mismatch detection for fuel/oil/AC pressure; tune-file engine map names (e.g. "Drag") read directly from the tune instead of a raw slot number; shift-button and traction-control counts use debounced event detection instead of raw sample counts, which were overcounting by 5-6x.
